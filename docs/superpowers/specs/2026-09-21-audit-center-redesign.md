# 审计中心重构设计

## 目标

将原有“历史数据、数据对比、基础审计、实时审计、恢复当前数据”混杂的页面重构为面向数据管理员的审计中心，提供三项职责清晰的功能：历史批次管理、采集问题总览、问题明细复核。

本次改造不改变采集器的采集协议，也不把现场数据上传远端。问题中心只读取本地批次数据和报告，并将普通采集问题与实时采集问题统一展示。

## 页面结构

### 历史批次

使用时间轴或紧凑列表展示可用批次。每行固定显示：

`完成时间 - 用时 - 范围 - 卡片数量 - 采集模式 - 版本 - 删除`

字段规则：

- 用时由 `StartedAt` 与 `CompletedAt` 计算；缺失或非法时显示 `-`，不伪造时长。
- 采集模式只显示 `稳定模式` 或 `快速模式`。内部值 `stable-full` 映射为 `稳定模式`，`fast-batch` 映射为 `快速模式`；未知值显示 `-` 并保留原始值供诊断。
- 范围和卡片数量使用批次自身快照，不与其他批次数量比较。
- 保留批次选择能力，选择批次后进入采集问题页面时使用该批次。

删除操作：

1. 点击删除后执行只读预检查，解析批次 manifest、数据库身份和已登记 artifact。
2. 弹窗显示完成时间、范围、卡片数量、采集模式、版本，并明确提示将删除本地设备数据、JSON、NDJSON、质量报告和实时报告。
3. 用户确认后，在 SQLite 事务中删除该批次关联的设备数据、子区域数据、质量/实时关联记录和批次记录。
4. 事务成功后清理通过身份校验的批次文件；共享文件、latest 文件和无法证明归属的文件必须保留。
5. 任一文件清理失败都要显示失败路径和原因，不能把批次静默显示为已完整删除；数据库删除成功但文件残留时，反馈“批次数据已删除，部分文件清理失败”。
6. 删除完成后刷新历史批次、当前选择和问题中心；若已删除批次是当前批次，自动选择最新可用批次或显示无批次状态。

批次删除范围包括 SQLite 批次数据、批次 JSON、批次 NDJSON、质量报告和实时报告。日志不属于批次删除范围。

### 采集问题

页面右上角提供批次选择器。页面将普通质量问题和实时质量问题归并为同一个问题模型，按问题类型显示数量和严重级别。首版问题类型包括现有质量报告和实时报告已经能产生的类别：等待超时、默认值疑似、占位卡片、字段不完整、通讯状态未知、缺少 indicator、重复卡片、页面采集失败、实时字段异常、实时枚举异常、实时范围异常、实时锁定异常和实时点采集失败。

问题卡片只负责汇总和导航，不截断底层记录。点击问题类型后进入问题详情并自动带上该类型过滤条件。

### 问题详情

详情页默认显示所选批次的全部问题记录；从问题卡片进入时按问题类型筛选。筛选条件至少包括问题类型、严重级别、楼栋和关键词，且允许清除筛选恢复全部记录。

每条记录必须尽可能展示：

- 问题类型和严重级别
- 楼栋、展示楼层、座号/区域、页名
- 设备名称和设备编号
- 采集时间
- EMS 页面实际现象
- 原始采集值或报告证据
- 采集器判断
- 判断依据
- 问题归因：EMS 页面问题、采集器判断或两者待复核
- 处理状态：有效、拒绝或需复核

“全部记录”指生成器和读取层不能再只保留前 N 条样本。现有报告中被 `slice(0, 50)` 等限制截断的明细需要改为完整记录，摘要数量由完整记录计算。缺失位置或证据时显示 `-`，不使用猜测值填充。

## 统一问题数据模型

在 Application 层增加批次问题读取接口和统一记录模型，避免 Desktop 直接解析质量报告或实时报告的 JSON 结构。模型至少包含：

- `BatchId`、`BatchUid`、`IssueType`、`Severity`
- `Building`、`Floor`、`Zone`、`PageName`
- `DeviceName`、`DeviceId`、`CollectedAt`
- `ObservedValue`、`Evidence`
- `CollectorDecision`、`Reason`
- `Attribution`、`ResolutionState`
- `SourceArtifact`、`SourcePath`

适配器分别读取质量报告和实时报告，再由服务统一排序、计数和筛选。重复记录必须依据批次、问题类型、位置、设备和证据键去重；不同来源对同一设备提出不同问题时保留为独立记录并标记来源。

## 删除旧功能

从 Audit 页面、ViewModel、导航和命令中移除：

- 数据对比页及其筛选、加载和比较模型
- 恢复当前数据命令和相关 UI
- 独立的基础审计页和执行命令
- 独立的实时审计页和执行命令
- 与上述功能专属的状态、按钮、指标和数据绑定

质量报告和实时报告生成能力作为问题中心的数据源保留；不再提供单独的“运行审计”入口。已有底层服务只有在没有其他消费者时才删除，避免影响采集流程和批次文件生成。

## 设置：清空本地日志

在设置页增加独立的“清空本地日志”操作。默认清理配置数据目录下全部本地日志文件，包括应用、采集和审计日志；不按时间保留旧日志，也不触碰 SQLite、JSON、NDJSON、质量报告、实时报告、配置文件或导出文件。

执行前统计日志文件数量和总大小，弹窗要求确认。清理过程使用限定在配置数据目录内的路径校验，跳过正在写入的文件并报告跳过原因；完成后显示成功清理、跳过和失败数量。日志不存在时显示“没有可清理的本地日志”，不视为错误。

## 兼容和错误处理

- 旧批次缺少 `BatchUid`、`RunKey`、报告或完整元数据时，仍可出现在历史列表；无法安全绑定的 artifact 不删除，并在删除结果中说明。
- 旧报告无法解析时，问题中心显示该批次的“报告解析失败”问题记录，而不是让整个页面崩溃。
- 文件删除和 SQLite 删除不是一个可回滚事务；因此必须先预检查、再提交数据库事务、再逐项清理文件，并向用户报告部分成功状态。
- 当前批次或批次文件正在被采集任务使用时，删除操作拒绝执行并说明原因。
- 空批次、无问题批次和无历史批次必须有明确空状态，不显示虚构卡片或问题数量。

## 验收与测试

### ViewModel/服务测试

- 用时计算、稳定/快速模式映射和未知模式处理。
- 历史批次删除预览内容和 artifact 身份保护。
- SQLite 批次删除只删除目标批次，不影响其他批次。
- JSON、NDJSON、质量报告、实时报告全部清理；共享和 latest 文件保留。
- 删除部分失败时返回可见的逐项结果。
- 统一问题模型能合并普通与实时问题，并保留全部记录。
- 问题类型筛选、清除筛选和空状态。
- 日志清空只删除日志，路径越界和批次数据保护测试。

### UI 合约/实际页面测试

- 历史批次仅展示目标字段和删除入口。
- 对比、恢复、基础审计、实时审计入口均不存在。
- 问题卡片数量与详情全部记录一致。
- 从问题卡片进入后自动筛选对应类型。
- 删除确认弹窗展示动态批次信息和不可恢复提示。
- 设置页清空日志按钮的确认、结果和无日志状态。

### 回归门禁

- 现有区域组相关测试、Native Release 构建和 Node 自检不得回归。
- `git diff --check` 通过。
- 测试使用临时目录和临时 SQLite，不触碰 `out/ac.db`、现场 JSON/NDJSON 或远端数据。

## 实施顺序

1. 先抽取统一批次问题模型和读取服务，补齐报告生成器的完整明细。
2. 扩展批次 artifact 清理器和 SQLite 仓储，覆盖删除预览、身份保护和部分失败反馈。
3. 重构 Audit ViewModel 与页面为三页结构，移除旧命令和绑定。
4. 增加 Settings 日志清空服务、命令和确认交互。
5. 增加测试，执行构建、单元测试、页面合约测试和隔离目录端到端验收。
