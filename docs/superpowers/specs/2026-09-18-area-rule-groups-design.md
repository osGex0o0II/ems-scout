# 通用区域组匹配规则设计

## 目标

将区域页面从系统固定的“公区/非公区”和手工添加楼层/设备，改为可复用的区域组规则管理。区域组可以任意命名、编辑、停用、删除、导入和导出；创建并启用的区域组显示在总览、数据筛选和生产导出中，未命中任何区域组的设备显示 `-`。

## 已确认的业务语义

- 一个设备可以命中多个区域组；多个区域组可以重叠，也可以没有设备命中。
- 区域组内一条规则的字段关系是 `楼栋 AND 座号 AND 楼层 AND 关键词`。
- 同一区域组的多条规则按 OR 合并。
- 规则模式为“包含”或“不含”。包含规则先构成候选集合，不含规则从候选集合中排除；如果一个区域组只有不含规则，则在这些不含规则声明的楼栋/座号/楼层范围内取全集，再排除关键词命中的设备。
- 关键词使用 `|` 分隔，保存时去空格、去空项、忽略大小写；一条规则内命中任意关键词即可。空关键词禁止保存。
- 楼栋必选。1号至4号楼座号固定为 `-`；5号允许 A-F 座，6号允许 A-C 座；`-` 表示该字段不限制。
- 楼层使用展示值 `B1F`、`BM`、`1F`、`1.5F`、`2F`、`2.5F` 等；空楼层表示整栋楼。排序固定为 `B1F`、`BM`、`1F`、`1.5F`、`2F`、`2.5F`、`3F`……。
- 历史批次直接使用批次保存的 X 坐标推导出的已保存座号，不重新推算或依赖当前页面布局。
- 区域组停用后保留在区域管理中，但不出现在总览、数据区域筛选和导出结果中。
- 生产环境初始没有任何区域组和规则；开发/测试夹具可以显式加载公区和非公区示例，但不得写入生产初始数据。

## 数据模型

继续使用 `monitor_groups` 保存区域组身份，但清除其旧的系统组/成员语义，新增稳定的 `group_key`。新增 `area_group_rules` 保存规则：

- `id`, `group_id`, `rule_order`
- `building`, `zuo`, `floor_label`, `floor_value`
- `match_mode` (`include` / `exclude`)
- `keywords`（规范化后的 `|` 分隔文本）
- `note`, `created_at`, `updated_at`

旧 `monitor_group_items` 仅在一次性迁移中清空，不再被业务查询读取。迁移通过版本标记保证只执行一次，并且不触碰 cards、pages、批次、实时快照、日志和质量报告。`device_watch_rules` 继续关联区域组身份，但其成员查询改用新规则匹配。

## 代码边界

- Application：新增规则记录、编辑记录、规则规范化、楼层/座号选项和纯函数匹配器。
- Infrastructure：SQLite 迁移、区域组/规则 CRUD、JSON 导入导出、按规则读取设备和统计。
- Desktop：区域页改为组信息、备注、启停、规则编辑器、规则表格以及导入/导出；删除“更多组设置”和楼层/设备成员编辑流程。
- Dashboard/Data：只消费启用区域组；区域类型不再作为区域组来源，未匹配显示 `-`，数据页和 Excel 导出均按 `group:<id>` 筛选。
- Watch/Audit：通过同一个规则匹配器确定关注设备，不能保留旧成员表分支。

## 导入导出

区域页面导出的 JSON 只包含区域组配置和全部规则：版本、`groupKey`、名称、备注、启用状态、规则顺序、楼栋、座号、楼层、模式、关键词和规则备注。不包含设备实时状态、批次、SQLite、日志、质量报告、JSON/NDJSON 采集数据。

导入采用合并策略：`groupKey` 相同则更新区域组及其规则；不存在则新建；目标中未出现在文件里的区域组保留；导入不创建重复副本，也不清空全部区域组。导入在事务中完成，文件格式和规则字段先完整校验。

## 验证要求

- 单元测试覆盖字段 AND、组内 OR、包含/不含混用、只有不含规则、楼层归一化、座号限制和关键词规范化。
- SQLite 测试覆盖一次性迁移、CRUD、启停、删除级联、导入合并和导出脱敏边界。
- Dashboard/Data/Excel 测试覆盖重叠区域组、停用隐藏、未匹配显示 `-`、历史批次座号不被重算。
- UI 合约测试确认区域页使用备注、规则编辑器、导入导出按钮，并不再出现旧成员/系统区域文案。
