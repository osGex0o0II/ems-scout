# 历史数据管理设计

## 目标

将现有“审计中心 + 历史批次附属列表”调整为以历史数据批次为主对象的管理工作区，同时保留基础质量审计、实时点位审计、实时对账和安全恢复能力。

## 现状与边界

- `AuditPage` 当前把基础审计、实时审计、实时对账和历史批次放在双栏嵌套滚动布局中。
- `collection_runs`、`run_buildings`、`run_sub_areas`、`run_pages`、`run_cards` 已保存可恢复的历史快照。
- `ICollectionRunRepository.RestoreCurrentAsync` 已实现恢复前备份、全量/部分楼栋恢复和异常批次保护。
- 采集、导入、数据管理页不在本次重构范围内，但必须保持现有接口和行为。

## 设计

### 页面分层

保留现有导航入口和 `AuditPage` 路由，页面内部改为三个明确的工作区：

1. **历史数据**（默认）
   - 批次筛选、统计指标、批次列表和选中批次详情。
   - 批次是页面主对象，列表不再被审计面板挤压。
2. **数据对比**
   - 将选中历史批次与当前数据库比较。
   - 显示总卡片数量、楼栋覆盖、按楼栋数量差异、可识别的新增/缺失/字段变化摘要。
   - 恢复入口只放在对比区，先预览后确认。
3. **质量审计**
   - 保留基础质量审计、实时点位审计、实时对账、问题等级和刷新操作。
   - 这些内容只描述当前审计结果，不再承担历史批次浏览职责。

### 批次信息

批次列表及详情统一展示：批次 ID、完成时间、数据来源、范围、楼栋数量、卡片数量、版本、状态、是否当前版本、异常标记和质量摘要。

对于旧数据库中不存在的字段，迁移默认值如下：

- `source`: `采集导入`
- `data_version`: `v1.0.0`
- `operator`: `本机`
- `is_current`: 由最新完成且非备份批次派生，不依赖旧字段

### 筛选

筛选在 ViewModel 内完成，支持时间范围、楼栋、来源、状态和关键字。列表数据始终来自同一批次集合，避免筛选后统计数字与列表不一致。

### 对比与恢复

- 对比服务读取选中批次快照与当前 `buildings`/`cards` 数据，返回汇总和按楼栋差异。
- 无法可靠识别单卡字段变化时显示“数量可比，字段差异需查看批次详情”，不伪造精确结果。
- 恢复前必须完成对比加载，并通过 WinUI `ContentDialog` 二次确认。
- 异常、未完成、覆盖不全的全量批次继续禁止恢复。
- 恢复成功后重新加载批次、审计和对比状态；恢复前备份继续保留。

### 布局与交互

- 页面只保留一个外层垂直滚动区域，各工作区内部使用有限高度列表，不再出现左右双滚动区域。
- 顶部显示“最后更新时间”和刷新中状态。
- P1/P2 分开统计，并同时显示问题数量与当前审计对象比例。
- 高风险操作使用图标 + 明确文字、禁用态和二次确认。
- 页面最小尺寸下优先保证筛选栏、批次核心列和详情标题可见，窄窗口允许列表横向滚动但不发生文字重叠。

## 数据迁移

使用现有 SQLite 启动初始化路径执行幂等 `ALTER TABLE ... ADD COLUMN`，不删除、不重建用户数据。迁移失败时保留旧字段可读性并在状态栏显示明确错误。

## 错误处理

- 批次详情、对比、恢复和删除分别捕获异常，不能因单个批次损坏导致页面崩溃。
- 快照缺失时对比区显示不可用原因，恢复按钮保持禁用。
- 刷新期间禁止重复执行审计、恢复、删除和对比命令。

## 验证标准

- 旧数据库可打开，自动补齐新字段，现有历史批次仍可选择和恢复。
- 历史数据默认页能筛选、选中、查看详情。
- 对比页能展示汇总和楼栋差异，恢复必须经过对比和二次确认。
- 质量审计功能仍可运行，审计错误不导致页面退出。
- .NET 全部测试、Node 自检、数据校验、Release 构建通过。
