# 区域组 23 条故障修复计划

日期：2026-09-20

## 目标

修复区域组从创建、编辑、锁定、删除、导入导出，到数据页筛选、历史批次显示和总览统计的 23 条已确认问题。

修复后的约束：

- 区域组规则是设备分类和筛选的唯一来源；不恢复公区/非公区硬编码。
- 单条规则内部仍然是 `楼栋 AND 座号 AND 楼层 AND 关键词`；同组多条规则是 OR。
- 规则组和设备关注组职责分离。
- 当前批次只使用当前启用规则，历史批次只使用该批次保存的规则快照。
- 未匹配设备可被明确筛选，显示为 `-`。
- 锁定组不可被普通编辑、删除或导入覆盖。
- 所有保存、快照和删除操作在同一 SQLite 事务内完成。
- 现场数据、日志、质量报告、批次 JSON、NDJSON 和 SQLite 只留在本地，不进入远端仓库。

## 架构决策

### 1. 区域组与设备关注组分离

区域组以 `group_key` 非空且存在于区域组配置为身份边界；设备关注组保留在 `monitor_groups`，但 `group_key` 为空或使用独立类型标识。数据页和规则页只读取区域组，不再用 `enabled` 单独判断。

区域组是分类配置，关注规则是另一种用户功能。删除区域组时不静默删除关注规则：如果仍有关注规则引用该组，默认阻止删除并提示引用关系；只有用户明确执行二次确认并选择清理关联关注规则时才允许级联删除，并在审计日志中记录。

### 2. 历史规则快照

新增 `run_area_group_rules` 表，至少保存：

```text
run_id, group_key, group_name, enabled, rule_order,
building, zuo, floor_label, match_mode, keywords, note
```

导入新批次时，在写入批次和设备的同一事务中保存当前区域组规则快照。历史查询按 `run_id` 读取快照；旧批次没有快照时返回“规则快照缺失”，不能静默套用当前规则。

### 3. 保存模型

区域组元数据、规则行和规则快照统一采用事务边界。UI 使用“编辑中草稿”和“已保存状态”对比，刷新、切组、导入、新建前发现未保存修改时必须给出明确选择：保存、放弃或取消。

## 23 条问题与处理方案

### 1. 取消新建区域组不清空临时规则

根因：`CancelNewGroup` 只退出新建状态，没有清空草稿规则集合和临时组字段。

处理：在 `GroupsViewModel.CancelNewGroup` 中集中调用 `ResetDraft`，清空规则、错误、命中数、编辑标记和新建组临时 ID；取消后重新加载当前已保存组，禁止草稿对象继续被命令引用。

测试：新建组添加两条规则，取消，再次新建，确认规则为空且保存按钮不可用；取消后切换已有组，确认无残留。

验收：取消新建永远不产生规则行、不写数据库、不影响已有组。

### 2. 保存区域组和规则不是原子事务

根因：`SaveGroupAsync` 与 `SaveRuleAsync` 分开提交，组元数据成功而规则失败时会留下半保存状态。

处理：新增仓储级 `SaveConfigurationAsync`，一次事务完成组 upsert、规则删除/重建、排序校验、启用状态校验和版本更新；ViewModel 只调用该入口。失败时整体回滚，并保留编辑草稿和错误信息。

测试：模拟规则约束失败、重复排序和数据库异常，验证组字段和规则都回滚；成功路径验证一次事务内完整保存。

验收：数据库中不存在“组已保存但规则未保存”的中间结果。

### 3. 区域组与设备关注组共用 `monitor_groups`

根因：两个领域复用同一张表且调用方只看 `enabled`，导致规则加载、删除、统计互相污染。

处理：短期使用明确的类型/`group_key` 边界并集中封装 `IsAreaGroup`、`IsWatchGroup`；中期迁移为独立区域组表或增加不可混淆的 `group_type` 约束。所有读取入口只使用类型化仓储方法。

测试：分别创建区域组和关注组，验证区域列表、数据筛选、删除和导入互不影响；回归现有关注功能。

验收：任何区域组查询都不会返回关注组，任何关注组操作都不会改变区域规则。

### 4. 删除区域组会删除同组 `device_watch_rules`

根因：`DeleteGroupAsync` 以 `group_id` 直接删除 `device_watch_rules`，没有检查领域关系。

处理：删除前查询引用；默认阻止并返回可读错误，明确确认后才执行级联清理。级联必须与区域组删除在同一事务中完成，并写审计记录。

测试：有引用时普通删除失败且关注规则仍存在；确认级联时两者一起删除；删除失败时全部回滚。

验收：普通删除区域组不再静默丢失设备关注规则。

### 5. 锁定组仍显示“添加规则”

根因：UI 只绑定组存在状态，没有把 `IsLocked` 作为编辑能力门禁。

处理：ViewModel 暴露 `CanEditSelectedGroup`，所有新增、删除、保存命令统一使用；视图隐藏或禁用添加规则按钮并显示锁定状态。

测试：锁定组、未锁定组分别检查按钮状态和命令 CanExecute；通过键盘快捷操作也不能绕过。

验收：锁定组界面没有可执行的添加入口，后端也拒绝写入。

### 6. 锁定组的已保存规则仍可删除

根因：`DeleteRuleAsync` 缺少锁定校验，UI 禁用不等于后端保护。

处理：仓储删除前重新读取组锁定状态并拒绝修改；ViewModel 同步禁用删除命令。任何绕过 UI 的调用都得到明确异常。

测试：直接调用仓储删除锁定组规则、通过 ViewModel 删除、并发锁定后删除，均应失败。

验收：锁定组的规则不可添加、修改、删除和排序。

### 7. 导入按 `groupKey` 直接覆盖锁定组

根因：`ImportAsync` 将导入键视为无条件覆盖键，没有锁定校验、差异预览和确认。

处理：导入先解析、校验、生成差异摘要；发现已有锁定组时拒绝覆盖并列出冲突。未锁定组也不直接静默覆盖，必须由调用方明确选择“替换”或“跳过”；导入使用事务。

测试：导入同键锁定组、同键未锁定组、新键组、重复规则和非法字段；验证预览、选择和回滚。

验收：导入永远不会解除锁定，也不会无提示替换现有规则。

### 8. 修改规则字段后单条命中数不刷新

根因：规则字段变更没有触发异步重算，或旧请求结果覆盖新状态。

处理：规则行字段变更统一触发防抖重算；按规则生成稳定版本号，结果只允许写回当前版本；保存前和切换组前强制等待/取消未完成请求。

测试：逐项修改楼栋、座号、楼层、模式、关键词，确认命中数随字段变化；快速连续修改验证最终结果对应最后一次输入。

验收：显示的单条命中数永远对应当前编辑值，不显示旧请求结果。

### 9. 单条命中数误导为区域组最终贡献数

根因：单条计数独立统计，未说明同组 OR 去重、排除和重叠规则，用户把它理解为最终分组数量。

处理：明确拆分两个指标：`规则命中数` 和 `区域组最终去重数`；同组多规则重叠设备只计一次，未匹配和其他组归属按最终分类计算。UI 文案和 API 字段改为明确名称。

测试：两条规则重叠、规则包含/不含相反、跨组重叠场景验证两个指标。

验收：页面不再把单条命中数冒充区域组最终设备数。

### 10. 历史批次使用当前规则重新匹配

根因：历史查询从当前区域规则表读取配置，没有批次级规则版本。

处理：引入 `run_area_group_rules` 快照；历史设备分类、筛选、导出、统计统一按批次快照。规则改名、停用或删除后，旧批次结果保持不变。

测试：创建批次 A，修改规则创建批次 B，分别查询两个批次并比较分类；删除当前组后仍能读取 A 的快照。

验收：历史结果只由批次数据和该批次规则快照决定。

### 11. 历史批次区域下拉数量使用当前数据统计

根因：历史页面复用当前批次区域汇总，筛选选项数量没有按所选 `run_id` 重新计算。

处理：区域选项和数量查询必须携带 `run_id`，使用该批次设备与该批次规则快照生成；当前批次和历史批次不得共享缓存键。

测试：两个批次设备数量不同、规则不同、存在未匹配设备时分别验证下拉数量和结果总数。

验收：切换历史批次后，区域名称、数量、筛选结果和导出行数全部属于该批次。

### 12. 后端支持未匹配，数据页没有未匹配选项

根因：后端解析了未匹配值，但 `DataViewModel` 构造区域筛选选项时只读取已命名组。

处理：在所有有设备但未匹配区域组的批次中追加 `-`/“未匹配”选项；保持与表格显示相同的值编码，避免把空值和未匹配混为一谈。

测试：全匹配、部分未匹配、全部未匹配和无设备四种批次验证选项及筛选。

验收：用户可以筛选未匹配设备，数量与表格结果一致。

### 13. 导入 `groups:null` 或 `rules:null` 通过校验后发生空引用

根因：`AreaGroupTransfer` 校验层将 null 当作空集合，但 `ImportAsync` 遍历原始 nullable 属性。

处理：反序列化后立即规范化为不可变空集合；校验层和导入层共用规范化 DTO。对 null、缺字段、重复键、重复序号、非法模式分别返回错误，不进入数据库事务。

测试：`groups:null`、组内 `rules:null`、空数组、缺字段和合法空规则组全部覆盖。

验收：非法导入只显示错误，不抛未处理空引用，不改变现有配置。

### 14. 导出缺少 `Priority` 和 `AreaLabel`

根因：传输 DTO 只导出了部分组属性，导入后无法恢复排序优先级和显示标签。

处理：扩展导入导出契约，加入 `Priority`、`AreaLabel` 及必要的版本字段；保持向后兼容，旧文件缺失字段使用明确默认值并在预览中提示。

测试：导出复杂组配置，导入到临时数据库，再逐字段比较；验证旧版本文件。

验收：导出再导入后组身份、显示名、备注、优先级、启用状态和规则顺序一致。

### 15. 切换区域组、刷新、导入、新建静默丢失未保存编辑

根因：导航命令直接替换当前对象，没有 dirty 状态确认。

处理：实现统一 `HasUnsavedChanges` 和离开编辑器守卫；切换、刷新、导入、新建、关闭页面都走同一确认流程。取消操作保留当前编辑状态。

测试：每个离开入口分别在无改动、已改动、保存中、保存失败四种状态验证。

验收：任何用户可见的编辑不会被静默丢弃。

### 16. 删除已保存规则立即落库，与统一保存语义不一致

根因：`DeleteRuleRowAsync` 直接调用仓储删除，而新增/修改通过“保存区域组”提交。

处理：删除只从编辑草稿移除并标记 dirty；统一保存时提交删除。若产品需要“立即删除”，必须改名为明确的危险操作并二次确认；本次采用统一保存语义。

测试：删除规则后取消离开，确认数据库规则仍在；删除后保存，确认规则删除；保存失败确认草稿仍可恢复。

验收：新增、修改、删除规则的提交时机一致。

### 17. 楼层选项依赖当前 `floor_catalog`

根因：规则编辑器的楼层下拉只从当前目录读取，历史批次或新采集到的楼层可能不存在。

处理：楼层候选合并当前目录、当前设备数据和已保存规则快照；按统一自然序排序 `B1F, BM, 1F, 1.5F, 2F...`；保留 `-` 表示整栋楼。历史规则值即使已不在当前目录也必须可显示和编辑。

测试：目录缺失但设备存在、规则存在但设备已删除、特殊页和小数楼层排序场景。

验收：合法历史楼层不再因当前目录变化而消失，空楼层始终显示 `-`。

### 18. 所有规则行共用 `_ruleOptionsVersion`

根因：多个规则行共享请求版本号，修改一行会使另一行未完成的楼层请求被错误丢弃。

处理：将版本号移动到每个规则行 ViewModel，或使用按 `ruleId`/草稿行 ID 的取消令牌和请求字典；结果回写前同时校验行身份、字段版本和所属组。

测试：同时修改至少三行楼层，交错返回请求结果，确认每行只接收自己的最新结果。

验收：规则行之间不互相取消或覆盖候选数据。

### 19. `GroupSummaryRow` 把所有组设为 `IsCustom=true`

根因：汇总行由旧公区/非公区模型复制而来，未从持久化组类型读取。

处理：`IsCustom` 改为真实组类型映射，或删除该无意义属性，改用 `GroupType`/`IsAreaGroup`。添加测试覆盖系统组、区域组、关注组。

验收：汇总页不会把系统组、关注组伪装成自定义区域组。

### 20. 数据页/规则加载只检查 `enabled`

根因：查询条件只筛启用状态，没有筛选区域组类型，导致禁用关注组或其他旧模型进入列表。

处理：仓储提供类型化查询，所有数据页、规则页、总览、导出入口明确指定 `AreaGroup`；`enabled` 只决定是否参与当前匹配，不决定是否属于区域组。

测试：混合启用/禁用区域组与关注组，逐入口核对结果。

验收：类型和启用状态两个条件都正确生效。

### 21. 总览把规则数量显示为“已添加范围”

根因：旧 UI 文案把规则条数当作区域覆盖范围，语义不准确且无法反映最终匹配设备数。

处理：改为“规则数”或“匹配设备数”，分别绑定规则数量和批次最终去重数量；无规则组不显示，未匹配显示 `-`。不再使用“已添加范围”这个模糊文案。

测试：零规则、一条规则、重叠规则、历史批次分别检查文案和数值。

验收：总览每个数字都有明确含义且与对应页面一致。

### 22. 通用规则组保留公区/非公区统计字段

根因：通用区域组改造后仍沿用旧领域字段，统计默认零，用户会误以为数据缺失或规则未生效。

处理：删除或隔离公区/非公区专属字段及计算路径，统一改用“区域组最终匹配数、规则命中数、未匹配数”。数据库迁移前保留只读兼容映射，但新代码不再写旧字段。

测试：新建任意名称区域组、重叠组和未匹配设备，检查总览、数据页、导出和历史显示不出现旧统计。

验收：产品界面和 API 不再暗示系统强制存在公区/非公区。

### 23. 新建按钮未绑定加载状态

根因：加载、导入、刷新期间命令仍可执行，可能同时替换 ViewModel 状态或覆盖当前草稿。

处理：引入统一操作状态 `IsBusy`/取消令牌；新建、保存、导入、刷新、删除互斥执行，按钮和命令同步禁用；异常和取消都在 finally 中恢复状态。

测试：加载期间连续点击新建、导入期间点击刷新、保存期间点击删除，并发调用 ViewModel 命令，确认只执行一个合法操作。

验收：不会出现重复草稿、竞态覆盖、按钮永久禁用或异常后状态卡死。

## 实施顺序

### 批次 A：数据安全与权限

修改文件：

- `native/src/EmsScout.Infrastructure/Sqlite/SqliteAreaGroupRepository.cs`
- `native/src/EmsScout.Application/Groups/AreaGroupTransfer.cs`
- `native/src/EmsScout.Infrastructure/Sqlite/SqliteDeviceReadRepository.cs`
- `native/src/EmsScout.Desktop/ViewModels/GroupsViewModel.cs`
- `native/src/EmsScout.Desktop/ViewModels/DataViewModel.cs`
- `native/src/EmsScout.Desktop/ViewModels/GroupSummaryRow.cs`
- `native/src/EmsScout.Desktop/ViewModels/HomeViewModel.cs`
- `native/src/EmsScout.Infrastructure/Sqlite/Migrations/*` 或现有 schema/migration 入口

步骤：

1. 先增加类型边界和数据库约束，不改变现场数据库；所有迁移只在应用启动的本地数据库上执行。
2. 实现事务保存、锁定保护、删除引用保护和安全导入。
3. 修复 null 规范化和导出字段。
4. 补仓储集成测试和临时 SQLite 回滚测试。

失败标准：任何权限保护缺失、锁定组可写、导入可静默覆盖或事务出现半保存状态，都不能进入下一批次。

### 批次 B：编辑器状态与交互

修改文件：

- `GroupsViewModel.cs`
- 区域组编辑 View/ViewModel/命令绑定文件
- 规则行 ViewModel 和楼层候选加载服务

步骤：

1. 完成草稿重置、dirty 守卫和统一保存语义。
2. 加入每行独立请求版本和命中数防抖刷新。
3. 增加 `IsBusy` 互斥状态。
4. 用 ViewModel 命令测试替代依赖真实桌面的点击测试。

失败标准：任意入口可静默丢编辑、删除绕过保存、旧请求覆盖新结果，均不能通过。

### 批次 C：历史、匹配和统计

修改文件：

- `scripts/schema.sql` 或正式迁移文件
- `scripts/import.js`
- `SqliteDeviceReadRepository.cs`
- `DataViewModel.cs`
