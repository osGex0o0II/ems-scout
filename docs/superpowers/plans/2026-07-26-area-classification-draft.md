# 区域分类与自定义分组改进草案

状态：设计已确认（2026-07-27 用户拍板三项开放问题），待实施。

## 目标

让运维人员用“哪些设备自动纳入、哪些自动排除、哪些设备直接指定”的方式维护区域，而不是理解底层规则类型。区域规则在采集导入后自动重算，审计只保留变更记录和撤销入口。

## 已确认决定

- “公区”和“非公区”是初始分类组，不是不可变系统标签。
- 用户可以改名、删除，或转为任意自定义分组。
- 改名后，数据管理与 Excel 的区域分类名称同步改变。
- 删除或转为自定义分组后，原成员显示为“未分类”，不会静默归入其他分类。
- 分类组和自定义组均可由规则持续自动更新。
- 分类组之间允许重叠共存：设备可同时命中多个分类组，分类组支持设置优先级，数据管理与 Excel 默认显示最高优先级分类，并可查看设备命中的全部分类（2026-07-27 确认）。
- "未分类"设备在数据管理页默认突出显示（2026-07-27 确认）。
- `layout=group` 属性隐藏为内部实现：迁移生成的初始公区规则在后台保留该条件，规则界面只展示名称/楼层等用户可编辑条件，初始分类来源在文档与审计记录中说明（2026-07-27 确认）。
- 用户保存规则时查看当前数据预览；后续采集自动应用规则。
- 审计记录自动加入/移出和规则原因，不再逐次阻断正式成员更新。
- 不再将“审核后的真实成员”作为用户可见区块；改为只读的“本组设备”。

## 推荐信息结构

页面分为“区域分类”和“自定义分组”。

- 区域分类：设备可命中多个分类组，按显式优先级显示主分类，可查看全部命中；初始为公区与非公区。
- 自定义分组：可重叠的运维分组，不改变设备的主区域分类。
- 分类组改名、删除或转为自定义组时，必须显示受影响设备数量和分类结果预览。

每个组使用以下任务式区块：

1. 自动纳入
   - 设备名称包含多个关键词时，命中任一关键词即可纳入。
   - 可选择一个或多个楼层；选择的楼层持续纳入。
   - 显示“名称 N 条、楼层 N 个”的摘要。
2. 自动排除
   - 设备名称包含指定关键词时，不由自动规则纳入。
   - 显示“名称 N 条”的摘要。
3. 指定设备
   - 从设备目录直接加入。
   - 该设备不因自动规则不再命中而移出。
4. 本组设备
   - 只读结果列表与数量。
   - 保存规则前按当前数据预览；采集后自动刷新。

## 自动分类语义

自动规则按以下顺序计算：

1. 以楼层范围作为候选设备范围；未设置楼层时，候选范围为全部设备。
2. 若存在“名称包含”，候选设备必须命中其中任一关键词。
3. 命中“名称不包含”的候选设备被排除。
4. 指定设备始终属于本组。
5. 分类组之间允许重叠：设备按分类组的显式优先级显示主分类，并可查看全部命中分类；重叠不再视为冲突。没有命中任何分类组的设备显示为“未分类”，在数据管理默认突出显示，审计记录缺口。优先级必须由用户显式设置，不做隐式猜测。

## 迁移边界

当前 `DeviceAreaClassifier` 将 `layout=group`、公区关键词与 `QL-NNN` 例外硬编码为公区/非公区。实施时必须把这些事实迁移为可追溯的初始规则，确保现有数据的分类不会因升级无故变化。

当前 `area_public`、`area_non_public`、`floor`、`name_exact`、`name_keyword` 规则存储和“待确认正式成员”流程需要迁移。迁移后，筛选、Excel、质量审计、历史批次和实时对账都必须以新的分类组结果为唯一口径。

## 外部依据

Microsoft Intune 的官方筛选器采用可视规则构造器，明确提供 Include/Exclude 模式，并在设备状态更新时动态计算匹配结果：
https://learn.microsoft.com/en-us/intune/intune-service/fundamentals/filters

本项目采用同样的“包含 / 排除 / 预览”原则，但针对楼宇设备将规则文案收敛为运维人员可直接理解的任务动作。

## 已确认实现细节（2026-07-27）

- 规则重叠：允许共存，不阻止保存；分类组支持用户显式设置优先级，决定主显示分类，亦可查看设备命中的全部分类。
- 删除分类组后，“未分类”设备在数据管理默认突出显示。
- 初始公区/非公区规则的 `layout=group` 条件隐藏为内部实现，不作为用户可见条件展示。
