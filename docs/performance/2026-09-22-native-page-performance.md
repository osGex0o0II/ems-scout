# 原生页面性能改进 — 2026-09-22

## 范围与环境

用户授权执行此前的性能方案。修改基于 `973eb27`，在分支 `codex/native-page-performance` 的独立工作树完成。已安装程序基线为 1.0.74.0；原有 `area-rule-groups` 工作树及生产库保持原位，测试使用 SQLite Backup 副本。

此次样本为 6471 台设备、3 个采集批次、230 条区域规则（93/99/38）。这些数量仅描述样本，不是产品完整性门禁。

## 已实现

- 区域页：楼层发现改为只读投影；组统计使用纯读入口，避免每次打开页面写楼层目录并触发其他页缓存失效。相同楼栋共享楼层请求，数据版本变化后重新读取。
- 区域规则：200ms 防抖，只处理业务字段和发生变化的行；忽略 Record/序号等派生通知。保留尚未发布的脏行，取消旧任务并阻止旧结果覆盖。清理旧行事件；规则列表采用有限 Grid 视口和内部虚拟化滚动。
- 规则命中：缓存轻量设备快照；存在人工匹配修正时保留实时身份匹配与座号修正，避免“优化后漏计”。不为命中统计加载关注历史或区域成员统计。
- 数据页：读取和计算在后台执行。不可变快照、排序结果、联动选项按版本缓存；分页复用现有结果，默认首次查询同时提供列表和联动选项。
- 总览：基础数量用 SQL 聚合；完整总览以批次、数据库/实时来源版本、异常阈值为键缓存。同版本复访不重新调用明细 Search。
- 一致性：数据库版本使用持久只读连接的 `PRAGMA data_version`，识别外部 WAL 提交、路径切换、文件身份/变更时间；实时 JSON 文件创建/修改/删除及目录变化也使缓存失效。读取前后验证版本，持续变更时有限重试后提示重试。并发等待者共享构建，单个取消不破坏其他等待者，失败可重新构建。
- 导出：捕获一次完整查询结果，页面与 Excel 使用同一份快照；导出期间的新筛选不被旧响应覆盖。保留当前 13 列与按楼号分表契约，最终隔离库烟测通过。

## 为保持业务语义采用的取舍

1. 没有把所有筛选强制绑定到一份全楼快照。旧版先 SQL 筛选再进行实时绑定，楼栋范围还决定批次来源可用性。差分验证发现广域快照会扩大“来源未绑定”的影响。因此缓存键保留 SQL 候选范围；窄筛选第一次可构建独立候选快照，联动选项复用同版本的广域快照。默认页和翻页仍只准备一次。
2. 缓存使用仓储内聚的 partial 实现，未另建公共 snapshot provider 层；缓存行及嵌套集合冻结，避免共享 `RealtimeDetailSet` 的可变匹配游标。
3. 保留原有 `LoadAsync` 的兼容迁移路径，页面走新增纯读接口；未改采集、导入或数据库架构。新发现楼层在内存合并，不在读取时持久写回。
4. 首次总览仍会在后台准备区域/实时指标，整份准备后一次发布；本机首次仓储耗时约 236ms，目前未引入分阶段首屏或更复杂的物化表。
5. Windows SQLite 活跃连接不共享文件删除权限。原位覆盖可通过文件变更时间识别；切换数据库或 Dispose 后释放原句柄。现有应用恢复走数据库事务，不要求强行删除正在连接的文件。

## 实测（仓储层，非界面完整耗时）

测量工具：`native/tools/EmsScout.PerfProbe`。每次建立唯一隔离副本，各场景使用独立仓储/总览实例；“首次”指该实例首次调用，进程 JIT、OS 文件缓存可能已热。热调用各 20 次，记录 P50/P95 与累计分配。旧版基线为独立安装程序集探针的少量热调用，不把它标为 20 次 P95。

| 场景 | 旧版观测 | 新版首次 | 新版热 P50 | 新版热 P95 |
|---|---:|---:|---:|---:|
| 单栋楼层读取 | 124–135ms | 7.26ms | 0.54ms | 0.74ms |
| 93条规则楼层初始化（逐行→5栋共享） | 9814.75ms（回放） | 2.28ms | 1.77ms | 2.17ms |
| 50行设备查询 | 110–137ms | 185.77ms | 0.23ms | 0.38ms |
| 500行列表+联动选项 | 旧路径分别准备 | 229.83ms | 0.34ms | 0.53ms |
| 已准备结果翻页500行 | 每页重复准备 | 1.09ms | 0.20ms | 0.23ms |
| 总览 | 256–273ms | 236.07ms | 0.12ms | 0.27ms |
| 单条规则命中 | 原先重走全量查询 | 68.92ms | 0.95ms | 2.71ms |
| 230条规则批量命中 | 未单独建立基线 | 164.67ms | 67.12ms | 105.46ms |

500/1000 条合成规则批量命中的热 P95 分别为 145.94/288.67ms；规则只存在于探针内存中，没有写入生产库。

50行设备查询热调用累计分配由约 70MiB 降到约 0.01MiB，总览由约 161MiB 降到约 0.01MiB。缓存构建需要持有数据，这不代表进程常驻内存同等减少。首次设备查询未声称提速，改善主要来自离开 UI 线程和后续复用。
